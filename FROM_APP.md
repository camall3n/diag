4. **The design of S for M2 and M3, agreed in the app.** Please follow it, and raise any problem in PROGRESS.md before you deviate.
   - **Language:** terms are de Bruijn variables, literal `Val`s, pairing, and the function symbols `Run`, `Check`, `Sub`, `sz` and `diag`, plus whatever symbols the evaluation rules below need (an `Eval` symbol for expression evaluation with explicit fuel and environment is fine).      1. Propositional rules: assumption, →-introduction (discharging an assumption), modus ponens, and ↔ handled as two implications.
     2. ∀-introduction (fresh variable) and ∀-elimination, **instantiating only with a variable or a literal**, because ∀ ranges over actual values and a general term may be `none`.

12. **A roadmap addition, the user's decision: M8, the necessity theorem.** This answers the objection "it's just a convention" with a theorem. The old optional M8 becomes M9. Please update the milestone list in CLAUDE.md.
   - **The idea (worked out in the app):** call an agent A *fair* if it cooperates with every opponent B for which there is a *short* proof (length ≤ p(|B|), p a polynomial) that B cooperates with A. Call it *unexploitable* if A plays C only when the opponent plays C. For a propositional formula φ, let B_φ = "try every assignment; play C if one satisfies φ, else D" (it ignores the opponent). Then:
     1. if φ is satisfiable, there is a short proof that B_φ cooperates (a fixed general lemma, "if some assignment satisfies φ, the search returns C", plus the witness and its check), so a fair A plays C;
     2. if φ is unsatisfiable, B_φ plays D, so an unexploitable A plays D.
     Hence A(B_φ) = C ↔ SAT(φ). **Paper statement: if P ≠ NP, no polynomial-time agent is both fair and unexploitable.** Use P ≠ NP only. **Do not use ETH anywhere.** It has been claimed refuted (Oct 2026), so avoid "exponential lower bound" language.
   - **What to formalize in Lean: the logical core, abstractly.** Parametrize over a type of programs, an outcome function, a predicate "a proof of length ≤ ℓ exists that B cooperates with A", and the opponents B_φ with two hypotheses: (i) `outcome(B_φ vs A) = C ↔ SAT φ` and (ii) `SAT φ → short proof exists`. Prove `fair A → unexploitable A → (outcome(A vs B_φ) = C ↔ SAT φ)`. Complexity classes stay on paper.
   - **Important caveat to record:** instantiating (ii) needs a proof system with **induction** (to prove the general search lemma once, with a short proof). Our S has no induction, so in S the only proofs that B_φ cooperates go through evaluation, which costs about as much as the search. So the concrete instance is PA-style (Critch's setting, where opponents may run long), not our S. Note also that the hard opponents are slow, since B_φ searches. Make both points explicit in the theorem's docstring and in PROGRESS.
   - Post a short plan with `[REVIEW] awaiting FROM_APP #13` before implementing.
